# Relay Engine API — v1 (DRAFT — review gate for M1)

The wire contract between the engine and every client (desktop app, CLI, third parties).
Freeze this before building engine features; changes after freeze are additive until 1.0.

Status: **draft**. Open questions are listed at the end and block nothing except their own sections.

---

## 1. Conventions

- **Two planes, two listeners.** Control plane — management API, UI assets, WS, SSE —
  default `127.0.0.1:8000`, serving `/api/*` plus `/ws`. Capture plane — webhook ingestion
  only — default `127.0.0.1:8001` locally; its own deployment behind a wildcard-DNS zone
  when exposed publicly. Rationale: provider traffic is unauthenticated, noisy, and
  sometimes hostile; keeping it off the app surface means it can never degrade
  authenticated endpoints, and each side scales and deploys independently. Locally both
  listeners ship in one binary (`--control-addr`, `--capture-addr`); in cloud they are
  separate services.
- **Fidelity guarantee:** capture records the raw request target before framework
  normalization — original percent-encodings and casing, duplicate headers, header order,
  query order and separators. No rewrites, decoding, or reordering anywhere on the
  ingestion path. Engine constraint: read the wire-form URI straight from hyper;
  typed extractors that decode are forbidden on the capture route.
- All request/response bodies are UTF-8 JSON unless stated otherwise. Captured webhook
  bodies are preserved verbatim (see envelope encoding).
- Timestamps: RFC 3339 UTC, millisecond precision.
- Paths are unversioned; the envelope carries `"v": 1` and WS frames carry `"v": 1`.
  Breaking changes post-1.0 ship a parallel version during a deprecation window.
- A machine-readable OpenAPI doc will be generated from the Rust code and validated
  against this file in CI; this document is the source of truth.

### Error model

Non-2xx responses:

```json
{ "error": { "code": "no_such_channel", "message": "channel 'foo' does not exist" } }
```

| HTTP | Codes |
|------|-------|
| 400 | `bad_request`, `invalid_template`, `missing_vars`, `invalid_signature`, `stale_timestamp`, `history_unavailable`, `slow_consumer` (WS/SSE) |
| 401 | `unauthorized` |
| 402 | `quota_exceeded` (billing or `--max-channels`) |
| 404 | `no_such_channel`, `no_such_event`, `no_such_template`, `no_such_route` |
| 413 | `body_too_large` |
| 422 | `unknown_signing_profile`, `inline_secret_disabled`, `billing_not_configured` |
| 429 | `rate_limited` |
| 500 | `internal_error` |
| 503 | not ready (`/readyz`) |
| 504 | `request_failed` (plane timeout); replay timeouts are reported in-band via `delivery.error = target_timeout` |

Removed from earlier drafts: `channel_name_taken` (PUT is idempotent — slugs and
channels never conflict), `unsupported_scheme`. Billing adds
`billing_not_configured` / `billing_disabled` on the checkout route.

## 2. Authentication

- Default: **no auth**, bound to loopback. This is the local-first posture.
- `--token <T>` (or `RELAY_TOKEN`): every **control-plane** endpoint requires
  `Authorization: Bearer T`. The capture plane stays open — providers cannot present our
  token — so its protection is per-channel config (see open question 7).
  WS and SSE additionally accept `?token=T` because browsers cannot set headers on those
  upgrades. Query-param tokens leak into logs; header form is recommended wherever possible.
- CORS: disabled by default. `--cors-origin <url>` may repeat to allow browser clients.

## 3. Channels

A channel is a named capture point with its own buffer, config, and subscriber set.
Name grammar: `[a-zA-Z0-9_-]{1,64}`. Management lives on the control plane (`/api/…`);
ingestion on the capture plane. The planes never cross: a capture-shaped request hitting
the control plane or an API call on the capture port is `404 no_such_route`.

### 3.1 Addressing

| Exposure | Channel selected by | Provider-facing URL |
|---|---|---|
| Local engine | path prefix on the capture port | `http://127.0.0.1:8001/c/github/<suffix>` |
| Wildcard-DNS host (self-host public, cloud) | `Host` header — one hostname per channel | `https://gh.{zone}/<faithful path>` |

- Hosted hostnames are `{slug}.{capture-zone}`; slug grammar `[a-z0-9-]{3,63}` plus a
  reserved list (`api`, `app`, `www`, `admin`, …). Generated by default
  (`quiet-river-42`); vanity slugs claimable at creation; collisions → `409`.
- In hosted mode the channel owns the entire hostname, so the provider's path is captured
  exactly as sent — nothing stripped, nothing prefixed. On the local capture port the
  `/c/{name}` root is structural and only the suffix is user space; that is a documented
  loopback limitation (localhost has no wildcard DNS), not the wire format.
- Cloud/tunnel forwarding preserves fidelity end-to-end: the ingress records the event
  and delivers the same envelope over the listener connection; optional re-injection to a
  local target re-sends the original method/path/headers/body unchanged.

### 3.2 Create / update — `PUT /api/channels/{name}`   *(control plane)*

Idempotent. Creates if absent, updates mutable config if present (returns `201` on create,
`200` on update). Body is optional; omitted fields keep defaults.

```json
{
  "response_mode": "ack",              // "ack" (default) | "echo" | "static"
  "auth": null,                        // or {"bearer_env": "GITHUB_TOKEN"}: capture plane
                                      // requires Authorization: Bearer <that env value>
  "static_response": {                 // required iff response_mode == "static"
    "status": 200,
    "headers": [["Content-Type", "text/plain"]],
    "body": "ok"
  },
  "buffer": { "max_events": 1000, "max_age_s": 86400 }
}
```

Response:

```json
{
  "name": "github",
  "created_at": "2026-08-21T12:00:00.000Z",
  "response_mode": "ack",
  "buffer": { "max_events": 1000, "max_age_s": 86400 },
  "auth": null,
  "capture_url_local": "http://127.0.0.1:8001/c/github",
  "capture_url_hosted": null
}
```

`capture_url_hosted` is set when the engine knows its capture zone (cloud mode, or
`--capture-zone acme.capture.example.com` for self-hosters running their own wildcard DNS).

### 3.3 Capture — capture plane, any method

Everything arriving for a resolvable channel is captured verbatim: raw request target
(pre-normalization), method, query string in original order and encoding, headers in
arrival order with duplicates preserved, exact body bytes.

- Local addressing: `ANY /c/{name}` and `ANY /c/{name}/{suffix…}`; the event's `path` is
  the suffix after `/c/{name}` (`""` for the bare channel).
- Hosted addressing: any path on the channel's hostname; `path` is the full request path
  exactly as received on the wire.
- Unresolvable targets (unknown slug/host) get `404 no_such_channel` and are **not**
  captured — there is nothing to attach them to. Everything under a known channel *is*
  captured: unusual methods, oversized bodies (flagged `truncated`), even requests we
  answer non-2xx; `status_sent` records what we replied.
- Responses per `response_mode`:
  - `ack` — `200`, JSON `{"accepted": true, "event_id": "<ulid>"}`.
  - `echo` — `200`, mirrors the request's `Content-Type` and body. Covers Slack URL
    verification (`challenge` echo) and similar probe flows without special-casing.
  - `static` — returns `static_response` verbatim.

### 3.4 Other channel routes   *(control plane)*

| Route | Behavior |
|---|---|
| `GET /api/channels` | list descriptors |
| `GET /api/channels/{name}/events?limit=&cursor=` | history, newest-last; `cursor` = last `seq` seen; omit for oldest |
| `DELETE /api/channels/{name}` | drop channel, its buffer, and subscriptions (subscribers get `channel_closed`) |

## 4. Event envelope

One captured request ⇔ one immutable event. Field order and casing are contractual.

```json
{
  "v": 1,
  "id": "01JAVBXQ7G5W3T8R9SK2M4N6P8",
  "channel": "github",
  "host": "gh.acme.capture.example.com",
  "seq": 42,
  "received_at": "2026-08-21T12:00:00.123Z",
  "method": "POST",
  "path": "/push",
  "query": "debug=1",
  "headers": [
    ["Content-Type", "application/json"],
    ["X-Hub-Signature-256", "sha256=abc123"]
  ],
  "body": "{\"action\":\"opened\"}",
  "body_encoding": "utf8",
  "truncated": false,
  "status_sent": 200,
  "remote_addr": "140.82.115.1:44192"
}
```

- `id` — ULID: unique forever, lexically time-sortable. Never reused across restarts.
- `seq` — per-channel `uint64`, starts at 1, gap-free, monotonic while in memory.
  Resets on restart (buffers are volatile); `id` remains the durable identity.
- `headers` — array of `[name, value]` pairs in arrival order; duplicates preserved;
  names lowercased (header names are case-insensitive per HTTP).
- `body_encoding` — `"utf8"` or `"base64"` (any non-UTF-8 body, e.g. multipart binaries).
- `remote_addr` — best-effort; may be `null` (e.g. behind a proxy without forwarded headers).
- `host` — request authority verbatim (`Host` header / HTTP/2 `:authority`). In hosted
  mode this is the per-channel subdomain; recorded so replays can reconstruct absolute
  URLs and future custom domains need no envelope change.
- `status_sent` — what the capture plane answered (per `response_mode`). Captured ≠ 200.

## 5. Subscriptions

Two transports, identical payloads: WebSocket (bidirectional, multi-channel) and SSE
(simple, per-channel).

### 5.1 WebSocket — `GET /ws` (upgrade)

All frames are single JSON objects, `"v": 1` included on every frame.

**Client → server**

| type | payload | notes |
|---|---|---|
| `subscribe` | `{"type":"subscribe","id":"c1","channel":"github","from":"newest"}` | `from`: `"newest"` \| `"oldest"` \| integer `seq`; `id` is a client correlation id, echoed |
| `unsubscribe` | `{"type":"unsubscribe","id":"c1","channel":"github"}` | stops delivery; buffer untouched |
| `ping` | `{"type":"ping","id":"p1"}` | app-level; WS protocol pings also answered |

**Server → client**

| type | payload | notes |
|---|---|---|
| `ok` | `{"type":"ok","id":"c1","last_seq":42}` | subscribed; `last_seq` = newest seq at subscribe time |
| `error` | `{"type":"error","id":"c1","error":{"code":"no_such_channel","message":"…"}}` | request rejected; connection stays up |
| `event` | `{"type":"event","subscription":"c1","event":{ …envelope… }}` | envelope per §4 |
| `pong` | `{"type":"pong","id":"p1"}` | |
| `channel_closed` | `{"type":"channel_closed","channel":"github"}` | channel deleted; subscription gone |

**Delivery semantics**

1. After `ok` for `from: <N>`: backlog events with `seq >= N` arrive first, ascending,
   then live events. Live delivery resumes strictly above the last replayed `seq` —
   no gaps, no duplicates at the seam.
2. `from: "oldest"` replays the whole buffer; `"newest"` is live-only.
3. Ordering is guaranteed within a subscription; cross-subscription ordering is not.
4. Backpressure: each subscription buffers up to 1024 outbound frames. On overflow the
   server sends `error`/`slow_consumer`, then closes the connection. Clients reconnect
   with `from: <last seq received>`; dedupe by `seq` is unnecessary (see 1) but harmless.
5. Across restarts: buffers vanish; `seq` resets. Clients wanting continuity persist the
   ULIDs they've seen, re-subscribe with `from: "oldest"`, and skip by `id`.
   In-memory guarantees are at-most-once per connection; the history API makes recovery
   client-driven.

### 5.2 SSE — `GET /api/channels/{name}/sse?from=&limit=`

Same backlog-then-live semantics as §5.1. Frames:

```
id: <seq>
event: relay.event
data: {"v":1,"id":"…", …full envelope… }

```

Heartbeat comment line (`:`) every 15 s. Slow-consumer overflow closes the stream
(client re-connects with `Last-Event-ID`, honored as `from`).

## 6. Replay — `POST /api/replay`

Sends an event (stored, templated, or inline) to an arbitrary HTTP target and reports
the real delivery outcome synchronously.

Request:

```json
{
  "target_url": "http://localhost:3000/webhooks/stripe",
  "timeout_ms": 10000,

  "source": { "event_id": "01JAVBXQ7G5W3T8R9SK2M4N6P8" },
  // XOR "source": { "template": "stripe/invoice.paid@1" }
  // XOR "source": { "inline": { "method": "POST", "path": "/", "headers": [], "body": "…" } }

  "overrides": {
    "path": "/invoice.paid",
    "query": "",
    "headers": [["X-Debug", "1"]],
    "body": "{\"amount\": 4200}"
  },
  "vars": { "customer": "cus_QY0" },
  "signing": { "profile": "stripe-dev" }
}
```

Rules:

- Exactly one `source`. Precedence for the outgoing request: source → `overrides` → signing.
- Final path: `overrides.path` when given (replaces), otherwise the source's faithful
  path **appended** to `target_url`'s own path — `target_url` may be a bare origin or a
  base URL (`http://host/base` + `/invoice.paid` → `/base/invoice.paid`).
- `vars` interpolates templates (§7); unresolved placeholders → `422 missing_vars`.
- Signing applies last, over the exact bytes sent. Profiles resolve secrets out-of-band
  (env or engine config) so secrets never transit the API or logs. Inline `"secret"` is
  permitted for CI, gated behind `--allow-inline-secret`, and never echoed back.
- Response `200`:

```json
{
  "sent_event": { …envelope of what actually went out… },
  "delivery": { "status": 200, "duration_ms": 31, "error": null }
}
```

`delivery.error` carries `target_timeout` / connect failures; `status` is `null` then.

### 6.1 Signing schemes

Canonical strings over the **exact transmitted body bytes**:

| Scheme | Headers produced | Canonical input |
|---|---|---|
| `github` | `X-Hub-Signature-256: sha256=<hex>` | `HMAC-SHA256(secret, body)` |
| `stripe` | `Stripe-Signature: t=<unix>,v1=<hex>` | `HMAC-SHA256(secret, "<t>.<body>")` |
| `slack`  | `X-Slack-Request-Timestamp: <unix>` + `X-Slack-Signature: v0=<hex>` | `HMAC-SHA256(secret, "v0:<t>:<body>")` |

Each scheme ships with the provider's official test vectors as unit tests (M1 exit criterion).

Profiles live in engine config, not the API:

```json
{ "signing_profiles": {
    "stripe-dev": { "scheme": "stripe", "secret_env": "STRIPE_DEV_WHSEC" },
    "gh-local":   { "scheme": "github", "secret_env": "GH_DEV_SECRET" }
} }
```

## 6.2 Billing (M4, opt-in)

When the engine runs with billing enabled (`--billing-enabled` + Stripe config,
see docs/billing.md), these routes exist on the control plane:

| Route | Behavior |
|---|---|
| `GET /api/billing/plans` | plan catalog + current subscription |
| `GET /api/billing/subscription` | current subscription state |
| `POST /api/billing/checkout` | create Stripe Checkout Session → `{"url": …}` |
| `POST /api/billing/webhook` | Stripe-signed events; signature = §6.1 scheme; no bearer token |

Entitlement failures return `402 Payment Required`, code `quota_exceeded`.

## 7. Template fixtures

Versioned files, bundled with the binary and overridable in `templates/`:
`templates/{provider}/{name}.json`, referenced as `{provider}/{name}@{v}`.

```json
{
  "v": 1,
  "provider": "stripe",
  "name": "invoice.paid",
  "description": "Checkout-completed invoice payment",
  "signing_hint": "stripe",
  "request": {
    "method": "POST",
    "path": "/invoice.paid",
    "headers": { "Content-Type": "application/json" },
    "body": {
      "id": "evt_{{uuid}}",
      "created": "{{now_unix}}",
      "data": { "object": { "customer": "{{customer}}" } }
    }
  },
  "defaults": { "vars": { "customer": "cus_example" } }
}
```

- Placeholder syntax: `{{name}}` — resolved from request `vars`, else template `defaults`,
  else error. Built-ins: `{{uuid}}` (ULID), `{{now_unix}}`, `{{now_iso}}`.
- Object bodies interpolate structurally; string bodies interpolate textually.
  Non-string leaves pass through untouched.
- `signing_hint` pre-selects a profile in the UI/CLI; callers may override.
- Bundled starter sets at M1: GitHub (`push`, `pull_request.opened`, `issues.opened`),
  Stripe (`invoice.paid`, `checkout.session.completed`, `customer.subscription.deleted`),
  Slack (`message.channels`, `url_verification`).

## 8. Limits & defaults

| Setting | Default | Flag/env |
|---|---|---|
| Max captured body | 1 MiB (larger → `truncated`) | `--max-body-bytes` |
| Buffer per channel | 1000 events / 24 h | `PUT /api/channels/{name}` |
| WS outbound buffer | 1024 frames | fixed v1 |
| Heartbeat interval | 15 s | fixed v1 |
| Replay timeout | 10 s | `timeout_ms` per request |
| Max channels | 256 (soft; `409`-style reject beyond) | `--max-channels` |
| Channel name length | 64 | fixed |

## 9. Resolved questions (frozen at contract review)

1. **Event id**: ULID — shorter than UUIDv7, lexicographically sortable, first-class Rust crate.
2. **Capture ack**: `200 {"accepted":true,"event_id":…}` stays the default; providers that
   need empty or fixed bodies use `response_mode: "static"` (or `echo`). No per-provider
   special cases in the engine.
3. **Wildcard subscriptions**: deferred to v2; grammar intentionally unspecified.
4. **WS-originated traffic**: post-v1 on a separate surface; the envelope gains a `kind`
   field only when it ships (additive change).
5. **Fixture sharing**: single-file JSON bundle (`.relaypack.json`: manifest + templates);
   export/import ships with collections (M3).
6. **Self-hosted public TLS**: v1 documents Caddy/nginx with ACME DNS-01 wildcard certs;
   built-in cert management comes later.
7. **Abuse controls**: engine-side in v1 — per-slug token-bucket rate limit and body-size
   caps; channels may require a bearer token resolved from an env var (`auth.bearer_env`,
   §3.2). Tenant-level throttling belongs to the SaaS edge later.
8. **Custom domains**: post-v1. The ingress accepts only `{slug}.{capture-zone}` hosts until
   then; `host` is already recorded verbatim so no migration is needed.

## 10. Deltas from the Go POC

| POC | v1 |
|---|---|
| Two ports split by accident (:8000 HTTP, :9000 WS) | two planes split by design: control (`:8000`, `/api/*` + `/ws`) vs capture (`:8001` local, per-channel hosts hosted) |
| Global broadcast to all sockets | channels with scoped subscriptions |
| Token hardcoded, always required | loopback-open by default; opt-in token |
| `{method,url}` only, body dropped | full-fidelity envelope (headers, query, exact body) |
| No history, no replay | ring buffer + history + signed replay + templates |
